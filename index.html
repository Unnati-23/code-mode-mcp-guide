MCP · CODE MODE

Code Mode:
The new way agents use MCP

Companies are moving away from making AI agents call MCP tools one by one. With Code Mode, the agent writes a short program against a typed API instead. A secure sandbox runs that program, and only the final answer goes back to the model. This guide covers the architecture, the original research, the real numbers and a full build you can run on your laptop.

Unnati Tripathi · Co-founder & CEO, Master Labs · @aiwithunnati

Source: Read the original Cloudflare Code Mode post → “Code Mode: the better way to use MCP” · Kenton Varda & Sunil Pai · 26 September 2025
THE 60-SECOND VERSION

MCP connects an agent to external tools. Code Mode changes how the model uses them. Instead of listing hundreds of separate tools in the model's context and making one round trip per call, Code Mode turns MCP tools into a typed TypeScript API. The model writes a small piece of JavaScript that handles several operations together. That code runs in an isolated sandbox, so intermediate data never has to pass through the model. Only the result you need comes back.

01 / Architecture

Follow the customer lookup

Example request: “Find Maya's account and tell me how much her shipped orders total.”

Direct tool calling

The client usually sends the relevant tool descriptions and input schemas to the model. The model calls find_customer, reads the customer ID, then calls list_orders with that ID. The second call depends on the first. Every returned row reaches the model, which filters the shipped orders and answers.

Code Mode

The model sends one program to a single outer code tool. Inside the sandbox, the program finds the customer, passes the ID to the orders tool, filters the rows and adds up their value. The host returns a compact result, and the model uses it to write the answer.

What happens in one Code Mode call

  1. 01
    MODELWrites JavaScript against the generated TypeScript declarations.
  2. 02
    SANDBOXRuns the program. The customer ID and order rows stay here while the program works.
  3. 03
    HOST + MCP TOOLSReceive only the allowed tool calls, through bindings. The trusted host holds the credentials and enforces policy.
  4. 04
    MODELReceives only the selected fields, such as count, total and currency.
WHAT ACTUALLY CHANGES

Both approaches make the same two upstream lookups. What changes is who coordinates them and how much data reaches the model. The model can still make another code call if it needs clarification or more data.

Why models are good at this

Cloudflare's argument is that LLMs have seen huge amounts of real TypeScript during training, but very few synthetic tool-call examples. So they write code against an API more reliably than they handle long chains of tool calls. Code also handles loops, branching and filtering naturally, which tool-calling has to do one round trip at a time. [1]

02 / Architecture

Where the tokens go

Tool definitions take up context before anything runs. Tool outputs take it up again when the model reads them. Code Mode cuts down both.

Two ways to expose tools

1 · One code tool

Generate TypeScript declarations from an existing MCP tool catalog and put them in the description of one outer tool. The model sees every available function up front. This works well for a compact catalog.

2 · search + execute

Keep the full OpenAPI document on the server side. The model searches it for the operations it needs, then writes a program that calls them. Discovery results and output still cost tokens, but advertising the two tools stays cheap however many endpoints you add.

What the published numbers measure

1.17M → 1,000≈ 99.9% · CLOUDFLARE API

Tool-definition tokens for exposing the full Cloudflare API directly, compared with advertising two Code Mode tools. Counted with tiktoken. [2]

9,400 → 600≈ 94% · INTERNAL PORTAL

Four internal MCP servers, with 52 tool definitions collapsed into two outer definitions. [10]

150,000 → 2,000≈ 98.7% · ANTHROPIC EXAMPLE

Fetching a meeting transcript and updating Salesforce. The workflow loads only the relevant tool definitions and processes intermediate data in code. [3]

A NOTE ON THE NUMBERS FROM THE REEL

None of the primary sources I reviewed back up a 150,000 → 60,000 comparison. Cloudflare introduced the Code Mode pattern described here. The 150,000 → 2,000 example comes from Anthropic's engineering post. Use the sourced figures above.

03 / Local build

Build it yourself

You'll run a real MCP server with two read-only tools on your own machine and expose it two ways: the classic /direct route and a Code Mode /mcp route. Both use the same fake records, so you can compare them directly.

WHAT YOU NEED

A recent Node.js LTS release, npm, Wrangler and the MCP Inspector. The Inspector lets you send the program by hand, so you can try the architecture without a model API key or a cloud deployment. Hosted Dynamic Workers are listed on the Workers Paid plan. [7] Cloudflare labels Code Mode experimental, so check the current docs before relying on it in production. [4]

STEP 1Install the dependencies

TERMINAL
mkdir codemode-orders-lab
cd codemode-orders-lab
npm init -y
npm i @cloudflare/codemode agents @modelcontextprotocol/sdk@1 @modelcontextprotocol/server@2.4.0 zod
npm i -D wrangler
mkdir src

Keep package-lock.json and use npm ci to reproduce the install exactly.

Why the extra package? Newer releases of agents (0.33 and later) import @modelcontextprotocol/server, and npm doesn't install it for you. Without it, wrangler dev fails with Could not resolve "@modelcontextprotocol/server". This lab was tested on 7 Nov 2026 with agents 0.33.0, @cloudflare/codemode 0.5.6 and wrangler 4.158.0, with no Cloudflare login.

STEP 2Add the Worker Loader binding

Save this as wrangler.jsonc at the project root. LOADER is the binding the SDK uses to create the isolated runtime.

WRANGLER.JSONC
{
  "name": "codemode-orders-lab",
  "main": "src/worker.mjs",
  "compatibility_date": "2026-11-07",
  "compatibility_flags": ["nodejs_compat"],
  "worker_loaders": [{ "binding": "LOADER" }]
}

STEP 3Create two MCP tools

These are the upstream MCP tools. Both handlers use sample data and return structured results, with a text fallback for MCP clients.

SRC/ORDERS.MJS
import { McpServer } from "@modelcontextprotocol/sdk/server/mcp.js";
import { z } from "zod";

const customer = { id: "cust_101", email: "maya@example.com" };
const orders = [
  { id: "ord_001", status: "shipped", totalPaise: 129900 },
  { id: "ord_002", status: "processing", totalPaise: 45000 },
  { id: "ord_003", status: "cancelled", totalPaise: 9900 },
];

function reply(data, isError = false) {
  return {
    isError,
    structuredContent: data,
    content: [{ type: "text", text: JSON.stringify(data) }],
  };
}

export function createOrdersServer() {
  const server = new McpServer({ name: "demo-orders", version: "1.0.0" });

  server.registerTool(
    "find_customer",
    {
      description: "Find a demo customer by email.",
      inputSchema: { email: z.string().max(254) },
    },
    async ({ email }) => {
      const found = email.trim().toLowerCase() === customer.email;
      return reply({ customer: found ? { id: customer.id } : null });
    },
  );

  server.registerTool(
    "list_orders",
    {
      description: "List a demo customer's orders in INR paise.",
      inputSchema: { customerId: z.string().max(64) },
    },
    async ({ customerId }) => customerId === customer.id
      ? reply({ orders })
      : reply({ error: "Unknown customer ID" }, true),
  );

  return server;
}

STEP 4Wrap the MCP server

/direct exposes the original tools. /mcp exposes the same tools through code, with the sandbox's network access blocked.

SRC/WORKER.MJS
import { DynamicWorkerExecutor } from "@cloudflare/codemode";
import { codeMcpServer } from "@cloudflare/codemode/mcp";
import { createLegacyMcpHandler } from "agents/mcp";
import { createOrdersServer } from "./orders.mjs";

export default {
  async fetch(request, env, ctx) {
    const path = new URL(request.url).pathname;
    if (path !== "/mcp" && path !== "/direct") {
      return new Response("Not found", { status: 404 });
    }

    const upstream = createOrdersServer();

    if (path === "/direct") {
      const direct = createLegacyMcpHandler(upstream, { route: path });
      return direct(request, env, ctx);
    }

    const executor = new DynamicWorkerExecutor({
      loader: env.LOADER,
      globalOutbound: null,   // no network access from the sandbox
      timeout: 5000,
    });

    const server = await codeMcpServer({ server: upstream, executor });
    const handler = createLegacyMcpHandler(server, { route: path });
    return handler(request, env, ctx);
  },
};
WHAT EACH ROUTE ADVERTISES

/direct lists the customer and order tools separately. /mcp advertises one outer code tool, and its description includes the generated types. Both routes share the same handlers and sample records. The executor has a 5-second timeout. The host can still call the permitted tools through bindings. The demo has no authentication, so keep it on localhost.

STEP 5Run the workflow

TERMINAL
# Terminal 1, from the project folder
npx wrangler dev --ip 127.0.0.1 --port 8787

# Terminal 2
npx -y @modelcontextprotocol/inspector@v1-latest

In the Inspector, choose Streamable HTTP and connect to http://127.0.0.1:8787/mcp. Under Tools, list the tools, select code and paste this JavaScript into the code field:

CODE TOOL INPUT
async () => {
  const { customer } = await codemode.find_customer({
    email: "maya@example.com",
  });
  if (!customer) return { found: false };

  const { orders } = await codemode.list_orders({
    customerId: customer.id,
  });

  const shipped = orders.filter(order => order.status === "shipped");
  return {
    found: true,
    shippedCount: shipped.length,
    totalPaise: shipped.reduce((sum, order) => sum + order.totalPaise, 0),
    currency: "INR",
  };
}

Expected result: {"found":true,"shippedCount":1,"totalPaise":129900,"currency":"INR"} in the tool response. That's INR 1,299.00, from one outer call.

STEP 6Try the direct path

Reconnect to http://127.0.0.1:8787/direct. Call find_customer with {"email":"maya@example.com"}, then pass {"customerId":"cust_101"} to list_orders. This route makes two calls and returns all three order rows, which a model would then have to read and filter itself.

04 / Real integration

Connect it to a real agent

Once the Inspector works, the next step depends on which side of the MCP connection you own.

If you publish the MCP server

Point a model-enabled MCP host at the authenticated /mcp endpoint. Enable the code tool and ask it for Maya's shipped-order count and total. The trace should show one outer call that does both upstream lookups. Keep the hand-written Inspector input as a regression check.

For a real service, replace the fake handlers with scoped CRM and orders clients. Pass the authenticated caller into the server factory and enforce tenant access inside every handler. Remove the public /direct comparison route before you deploy.

If your agent already connects to MCP servers

On the agent side, use Cloudflare's managed MCP connections and wait for them to connect before you collect their AI SDK tools. For a compact read-only catalog, pass this.mcp.getAITools() and a DynamicWorkerExecutor to createCodeTool(), then register the result in your model loop. If calls need on-demand discovery, approvals or resuming after a pause, use the documented McpConnector and durable runtime. [9] [12]

If you own a large OpenAPI catalog

Use openApiMcpServer({ spec, executor, request }) on your MCP route. Supply a trusted request callback that validates the method, path, query and caller scope, and attaches credentials on the host. Start with allowlisted read operations. search can query codemode.spec(), and execute can use codemode.request() to call the selected operations. [4]

KEEP THE BOUNDARY CLEAR

Leave general sandbox network access disabled. Bind only the tools the task needs, validate their arguments, and keep secrets out of sandbox globals, logs and returned data. Enforce write approvals on the trusted side before anything with side effects runs.

05 / Evaluation

Measure before you scale

Use the direct endpoint as your baseline. The local fixture checks correctness, but only a representative workload tells you whether the architecture saves time or tokens for you.

STEP 7Run a paired comparison

Keep the model version, prompt, task set, backend records, context limits and permissions the same on both paths. Start new sessions, or hold cache conditions constant. Run each case several times and compare by task. Cover one lookup, dependent calls, a paginated response, a no-match case and an upstream failure.

Record separate measurements: model input and output tokens across all turns, model calls, upstream calls, wall-clock latency and task success. Report cached input separately if your provider shows it. Track tool-definition tokens as their own estimate, and count code generation, discovery output, runtime cost and retries too.

Token saving % = (direct tokens − Code Mode tokens) ÷ direct tokens × 100

Use your provider's usage numbers for total model tokens. For tool definitions alone, serialise both catalogs the same way and count them with the same tokenizer. Report what you counted and which cases failed.

STEP 8Check the failure paths

  • In the Inspector, change the email to a customer that doesn't exist. The result should say there's no match and skip the order lookup.
  • Call list_orders in a code snippet with an unknown ID. Check that an MCP tool error comes back, not something that looks like a valid empty order list.
  • Try async () => (await fetch("https://example.com")).status. It should fail, because the sandbox has no outbound access.
  • For a real backend, limit calls, rows, output size and time per run. Retry transient reads up to a cap. Require approval for writes, use idempotency keys where they're supported, and report partial failures clearly.
COMMON SETUP ISSUES

If Wrangler can't see LOADER, check the binding name and start from the project root. If the Inspector shows no tools, check the port, the path and that you picked Streamable HTTP. If the build says it can't resolve @modelcontextprotocol/server, run npm i @modelcontextprotocol/server@2.4.0 and restart Wrangler. If port 8787 is already in use, pick another port, such as --port 8799, and use it in the Inspector URL. If other SDK imports fail, compare your installed versions with the current Cloudflare build guide. [4]
